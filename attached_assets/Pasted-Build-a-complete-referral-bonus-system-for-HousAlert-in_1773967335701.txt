==================================================
GOAL
==================================================

I want users to be able to invite friends to HousAlert using a personal referral code.

The feature should work like this:
1. Every user has a unique personal referral code
2. The user can view and copy that code from the app
3. A referral promo card is shown in the UI (similar to the Stekkies examples)
4. Tapping the CTA opens a modal with the referral code and explanation
5. New users can enter a referral code during signup / onboarding / subscription flow
6. The system validates the code and links the referred user to the referrer
7. The referral is stored in the database
8. The reward logic is prepared properly

For now, build the reward system as a solid MVP:
- store referral relationships
- mark referral status
- prepare fields for reward eligibility and payout
- actual financial reward application can be done in a safe, simple first version

BUSINESS LOGIC (MVP)
==================================================

Implement the referral system with these rules:

### Personal referral code
Each user should have a unique referral code.

Requirements:
- generated automatically for each user
- stable (does not change every session)
- reasonably readable
- unique across all users

Suggested format:
- based on name + random suffix
- example: MARTIN87 or HOUS-MARTIN-4821
- sanitize and uppercase if needed

### New user flow
A new user should be able to enter a referral code during signup or onboarding.

Add a referral code input in the most logical place:
- preferably onboarding or account creation flow
- if that is difficult, add it in a post-signup onboarding step before plan activation

Field behavior:
- optional field
- user can skip it
- validate code on submit
- show clear success or error feedback

### Validation rules
- referral code must exist
- user cannot use their own code
- user cannot apply more than one referral code
- referral code should only be applied once per referred user
- already processed referrals should not be duplicated

### Referral relationship
When a valid code is used:
- connect referred user to referrer
- store this relationship in the database
- set status for this referral

Suggested statuses:
- pending
- qualified
- rewarded
- cancelled

For MVP:
- create the status structure properly
- at minimum, store as pending or qualified depending on your implementation point
