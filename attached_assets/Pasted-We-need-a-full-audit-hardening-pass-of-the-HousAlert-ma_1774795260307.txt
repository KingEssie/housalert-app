PART 3 — DEFINE HARD FILTERS VS UNKNOWN-SENSITIVE FILTERS
==================================================

Implement and/or verify this rule set:

----------------------------------
HARD FILTERS
----------------------------------
These should be strict:
- location (city / district / radius)
- max rent
- min rent (if used)
- property type
- bedrooms / rooms minimum
- area minimum

Behavior:
- if listing clearly fails → reject
- if required field is missing and the system cannot safely compare → report current behavior
- do NOT silently pretend it matches unless there is already an intentional business rule

----------------------------------
UNKNOWN-SENSITIVE FILTERS
----------------------------------
These must support 3-state logic:
- furnished
- pets_allowed
- balcony
- garden
- bath
- roof_terrace
- energy_label
- elevator

Behavior for these filters:
If user explicitly wants a feature (for example balcony = yes):
- listing true → include
- listing false → exclude
- listing null/unknown → include ONLY if unknown-toggle is ON

If user does not care about that feature:
- do not filter on it

This rule must be implemented consistently for all supported optional feature filters.

==================================================

"Stuur mij woningen waarbij mijn eisen niet duidelijk staan aangegeven"

We need exact intended behavior:

If toggle = OFF:
- listings with unknown values for explicitly requested optional filters must be excluded

If toggle = ON:
- listings with unknown values for explicitly requested optional filters may still be included
- BUT known mismatches must still be excluded

Example:
User wants balcony = yes

Listing balcony:
- true → include
- false → exclude
- null → include only when toggle ON

Implement/verify this exact logic for all supported optional feature filters.

IMPORTANT:
The toggle must NOT turn false into true.
It only allows unknown values to pass.
