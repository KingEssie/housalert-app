1. FIX PAID SUBSCRIPTION PERIOD LOGIC
========================================

Audit Stripe checkout/webhook/subscription sync logic:
- checkout.session.completed
- customer.subscription.created
- customer.subscription.updated
- updateSubscriptionFromCheckout
- any trial_end/current_period_end mapping

Bug:
Paid 2-month subscriptions are being treated as trial subscriptions or using trial_end/current date + 14 days.

Correct behavior:
- If Stripe subscription status is trialing, use trial_end as access end.
- If Stripe subscription status is active paid, use current_period_end as access end.
- Never use trial_end for active paid subscriptions unless status=trialing.
- Never set 14-day trial end for a paid plan that has already started.
- Plan label must reflect Stripe price/product:
  - 2-month plan = “Premium 2 maanden”
  - monthly plan = “Premium maandelijks”
  - trial only = “Proefperiode”

Cancellation behavior:
- If active paid subscription is canceled at period end:
  - keep premium access until Stripe current_period_end
  - show “Loopt af op [real Stripe current_period_end]”
  - do NOT shorten access to 14 days
- If trialing subscription is canceled:
  - keep access until trial_end
  - show proefperiode text

Add defensive logic:
- If status=active and current_period_end exists, current_period_end wins.
- If status=trialing and trial_end exists, trial_end wins.
- If both exist, choose based on Stripe status, not whichever date is earlier.

Add logs:
- Stripe subscription id
- status
- trial_end
- current_period_end
- selected access_until
- selected plan label
- cancel_at_period_end

Smoke test:
- Buy 2-month plan
- Subscription page shows Premium 2 maanden
- End date is 2 months from purchase, not 14 days
- Cancel it
- Page shows active until same 2-month end date
- No cancel button after cancellation
- Premium access remains until that date
