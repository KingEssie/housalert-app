1. FIX BUDDY MATCH ALERT EMAIL LANGUAGE
==================================================

File:
server/notifications/buffer.ts

Current bug:
Buddy match alert emails and push notifications are sent using the OWNER's language.

This is incorrect.

Required fix:
Whenever sending alerts or push notifications to a buddy, fetch the BUDDY's own language from user_profile_data using the buddy's user ID.

Do this in BOTH code paths:
- flush path
- backfill path

Specifically fix:
- sendBatchMatchAlert(...) for buddy recipients
- sendMatchPushNotifications(...) for buddy recipients

Logic:
- owner alerts use owner language
- buddy alerts use buddy language

If buddy has no stored language:
- fall back to English first if that is the app fallback standard
- otherwise use the existing centralized locale fallback logic
- do NOT fall back to owner language for buddy alerts

2. FIX BUDDY INVITATION EMAIL LANGUAGE WHEN BUDDY ALREADY HAS AN ACCOUNT
==================================================

Files:
- server/routes.ts (POST /api/buddy/invite)
- any other invitation call sites

Current bug:
Invitation email currently uses:
- owner's request Accept-Language
OR
- owner's stored language

This is wrong when the invited buddy already has an account.

Required behavior:
If invited email belongs to an existing user account:
- fetch that user's stored language
- send invitation email in that buddy's language

If invited email does NOT belong to an existing user account:
- use owner's STORED language from DB as fallback
- do NOT use transient Accept-Language request header
