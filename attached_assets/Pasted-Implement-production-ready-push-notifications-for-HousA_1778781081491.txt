Implement production-ready push notifications for HousAlert mobile/PWA app.

Goal:
Users must receive instant push notifications when new housing matches are found.

IMPORTANT:
Do not break existing email notifications.
Do not break in-app notifications.
Do not change matching logic except adding push delivery after matches are created.

Brand:
Notification title examples:
- “Nieuwe woningmatch gevonden”
- “Nieuwe matches in Berlijn”
Body example:
- “Er zijn 3 nieuwe woningen gevonden die bij je zoekopdracht passen.”

==================================================
1. DEVICE TOKEN REGISTRATION
==================================================

Add backend support for storing push subscriptions/tokens.

Create table if missing:
push_devices:
- id
- user_id
- platform: ios | android | web | unknown
- token
- provider: expo | fcm | apns | webpush
- device_name nullable
- enabled boolean default true
- last_seen_at
- created_at
- updated_at

Add routes:
POST /api/push/register
- requires authenticated user
- stores/upserts token
- updates last_seen_at
- supports multiple devices per user

POST /api/push/unregister
- disables/removes token for current user/device

GET /api/push/status
- returns whether current user has active push device(s)

==================================================
5. SEND PUSH ON NEW MATCHES
==================================================

When new user_matches are created:
- collect affected user_id(s)
- send push notification to each user with active devices
- avoid duplicate push spam

Rules:
- If 1 new match:
  title: “Nieuwe woningmatch gevonden”
  body: “[city] · €[price] · Bekijk de woning”
  data: { listing_id, match_id, url: "/listing/:id" }

- If multiple new matches for same user/profile:
  title: “Nieuwe matches gevonden”
  body: “We vonden [count] nieuwe woningen voor [profile_name].”
  data: { url: "/matches" }

Batching:
- group matches created in same run per user/profile
- send max 1 push per user/profile per ingestion/backfill run
- do not send push for old backfilled matches during account creation unless explicitly enabled
- for new signup backfill, default: no push spam; just show matches in app
