--------------------------------
DATABASE
--------------------------------

Create or update a subscriptions table in Supabase with:

- id uuid primary key default gen_random_uuid()
- user_id uuid not null references auth.users(id) on delete cascade
- status text not null default 'trial'
  allowed values:
  - trial
  - active
  - canceled
  - expired
- plan text
  allowed values:
  - monthly
  - two_month
  - three_month
- trial_ends_at timestamptz
- current_period_ends_at timestamptz
- stripe_customer_id text
- stripe_subscription_id text
- created_at timestamptz default now()
- updated_at timestamptz default now()

Add a unique constraint on user_id.

After a new user signs up:

API ENDPOINTS
--------------------------------

Create:

1) POST /api/checkout/session
Input:
- plan

Behavior:
- ensure the current user exists
- create Stripe customer if needed
- create Stripe checkout session
- return checkout url

2) GET /api/subscription/status
Return:
- status
- plan
- trial_ends_at
- current_period_ends_at
- isActive boolean
- isTrial boolean
- isExpired boolean

3) POST /api/stripe/webhook
Handle events:
- checkout.session.completed
- customer.subscription.created
- customer.subscription.updated
- customer.subscription.deleted

Update Supabase subscriptions table accordingly.

--------------------------------
APP ACCESS RULES
--------------------------------

Build a reusable subscription gate.

Rules:
- if status = active → full access
- if status = trial and trial_ends_at is in the future → full access
- if status = trial and trial expired → restricted access
- if status = expired or canceled → restricted access

Restricted access behavior:
- user can still open the app
- but show a clear paywall banner or overlay on dashboard/matches
- blur or lock match content
- CTA: "Activeer je abonnement"

Do NOT fully block navigation.
Use a soft paywall.
