==================================================
GOAL
==================================================

Make the user-selected radius (km) in the search profile truly functional end-to-end.

Radius filtering must:
1. use real geographic coordinates
2. calculate distance correctly
3. include listings inside the selected radius
4. exclude listings outside the selected radius
5. behave safely when coordinates are missing

Do not guess.

==================================================
PART 2 — IMPLEMENT REAL DISTANCE FILTERING
==================================================

Implement true radius filtering in the active matching engine.

Requirements:
- use geographic distance based on:
  - search profile center point (lat/lng)
  - listing point (lat/lng)
- use a correct distance formula such as Haversine
- compare computed distance against the selected radius in kilometers
- if distance <= radius_km -> pass
- if distance > radius_km -> fail

IMPORTANT:
This must be real filtering, not city-name approximation.

==================================================
PART 3 — MISSING COORDINATES BEHAVIOR
==================================================

Define and implement the correct behavior when coordinates are missing.

If user selected radius mode and listing has no usable lat/lng:
- do NOT pretend the radius matches
- do NOT let send_unclear override missing geo logic
- treat the listing as not radius-matchable

If search profile center point has no lat/lng:
- radius filtering cannot work
- report/fix whatever is needed so the search profile stores usable center coordinates

IMPORTANT:
send_unclear is for unknown property attributes, not for missing geographic distance logic.

==================================================
PART 4 — LOCATION MODE BEHAVIOR
==================================================

Audit and fix the active search-location mode logic.

The system should clearly support:
- districts mode
- radius mode
- whole city mode

Required behavior:
1. Whole city mode
   - match by city only (existing behavior if already implemented)

2. Districts mode
   - match by district/neighborhood logic (existing behavior if already implemented)

3. Radius mode
   - match by actual distance calculation only

Make sure the matching engine respects the selected mode properly.
Do not let radius mode silently fall back to district or city matching unless explicitly designed.
