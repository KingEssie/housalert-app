This is the highest-priority source to improve first.

Goal:
Increase wg-gesucht image coverage significantly by improving extraction logic and adding better fallback behavior.

IMPORTANT:
- Focus only on wg-gesucht in this task
- Do NOT redesign UI
- Do NOT change unrelated scrapers
- Keep this source-specific and production-safe

==================================================

Inspect the current wg-gesucht ingester and identify:
- which selectors are used now
- whether extraction is done from overview page only or also detail page

- whether srcset is parsed

Log or summarize the current extraction path before changing it.

==================================================
2. ADD DETAIL PAGE IMAGE FALLBACK
==================================================

If the overview/list page does not provide a valid image:

- fetch the wg-gesucht detail/listing page
- try to extract the main image/gallery image from the detail page

Fallback order:
1. main configured selectors
2. gallery selectors
3. lazy-load attrs
4. srcset
5. og:image
6. twitter:image
7. first valid image inside article/main/gallery container

==================================================

For wg-gesucht specifically, check these attributes:
- src
- data-src
- data-lazy
- data-original
- data-lazy-src
- srcset

If srcset exists:
- parse it correctly
- choose the best usable image URL, not the tiniest thumbnail

==================================================
4. FILTER OUT PLACEHOLDERS / BAD IMAGES
==================================================

Detect and reject:
- placeholder images
- default fallback images
- blank/spacer images
- obviously invalid image URLs

If a placeholder is found:
- treat it as missing
- continue fallback extraction

Also normalize:
- protocol-relative URLs (//...)
- relative URLs
- malformed URLs if fixable
